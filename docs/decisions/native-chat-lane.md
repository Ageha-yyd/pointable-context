# Native Chat Lane

## 为什么需要决定

长任务中的压缩信息如果只能通过打开完整文件、离开当前任务或再发一轮 Chat 获取，会增加重新定位和理解成本。

## 选择了什么

首个产品宿主固定为 Codex Desktop 当前 Chat Lane：用户选中文字后，在原阅读位置附近打开有界详情卡。

## 后果是什么

用户可以原位获取详情且不新增 Chat Turn；当前能力范围也明确限定在 Codex Desktop，不能据此声称已跨宿主通用。

## 证据

> 当用户在 Codex Chat Lane 中读到压缩的文件、模块、概念、决策或任务状态时，可以选中相关文字，看到一个不打扰阅读的小型“查看上下文”入口；点击后在原阅读位置附近打开有界、可验证的详情卡，无需离开当前任务、打开完整文件或再发起一轮 Chat。
